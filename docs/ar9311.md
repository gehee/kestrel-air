# AR9311 / P1 Air backend

`make BACKEND=ar9311 CROSS_COMPILE=... ARLIBRE=...` builds the Linux V4L2
backend without HiSilicon SDK libraries. `BACKEND=hisilicon` remains the default.
Objects are separated by backend; the output executable is `kestrel-air`.

The AR9311 backend requires fpvOS's source SC231AI, CSI, VIF, ISP, CVISP and
Wave5 encoder drivers. The OS loads the modules and supplies board tuning.
Kestrel discovers video nodes by name, exports three-plane YUV420M capture
buffers as DMA-BUFs, and keeps them owned by the encoder until its OUTPUT queue
returns them. Only compressed HEVC bytes are copied into Kestrel's existing
packet ring. Radio framing and ar_libre transport are shared with the Lite.

The initial mode is 1920x1080 at 60 fps, complete-frame HEVC. With fpvOS's
Wave5 intra-refresh control, one CTU row is refreshed per picture (a complete
sweep in 17 pictures), and IDRs are sent on demand rather than every second.
The protocol advertises intra refresh so a receiver joining midstream asks
for a keyframe. Older kernels without this control retain the 60-picture GOP.
Runtime bitrate and keyframe requests use V4L2 controls. Slice output,
arbitrary resolutions, rotation, remote ISP tuning, recording, FC UART,
P1 temperature/battery telemetry are not implemented.
No HiSilicon MMIO or project-specific radio GPIO/ADC commands are used on P1.
Unassigned vendor board/sensor IDs are reported as zero; the model name identifies P1.

Wave5 uses a 17 ms rate-control reservoir and block-level rate control. The
reservoir shapes bitrate but is not a hard maximum encoded-frame size. Periodic
IDRs still caused roughly 100 ms delivery gaps with this reservoir; spreading
the refresh work removed that periodic burst in the bench trace. Explicit IDRs
remain necessary for joining and recovery, and can still cause a brief pause.

Run through fpvOS's `kestrel-air-run` launcher. It loads source camera drivers,
locks capture against the recorder, and provides:

- `KA_CAMERA_TUNING`: extracted, verified AE tuning file.
- `KA_WB_ORDER`, `KA_WB_RED`, `KA_WB_BLUE`: board-validated ISP statistics order
  and initial Q8 gains.
- `KA_CONFIG` and `KA_PEER_CONFIG`: writable application and paired receiver
  settings. P1 uses `/var/lib/kestrel-air`, separate from factory calibration.

Kestrel starts the source `ar9311-aed` and `ar9311-awbd` after eight capture
frames and stops its children when capture stops. A failed controller, a
stalled capture or a V4L2 error while streaming tears the encoder channel down
and starts a new one, controllers included, rather than streaming with dead
automatic controls. More than five such faults in a minute end the application,
a visible failure for the supervisor.

Provision this unit's radio configuration and saved peer before starting. The
stock JSON on disk can contain DEV-role defaults that its application changes
at runtime; do not feed it unchanged to AP Open8030. Preserve this unit's power
calibration and use native arlink framing, not the stock P1 SDIO block trailer.
The peer settings contain `bb_mac_addr_0` as four integer bytes. Missing settings
must not overwrite calibrated power offsets with Lite defaults.

`make test` checks the shared protocol helpers. `make test-ar9311` verifies that
a stale Lite board setting cannot activate its hardware controls on P1.
Hardware acceptance additionally requires a cold boot, radio association,
received HEVC validation and stop/restart testing; compilation alone is not it.

## Bind button and status indicators

P1 uses a device-tree `gpio-keys-polled` input named `p1-air-bind` and
`KEY_WPS_BUTTON`. Kestrel discovers the device by name and reads its current
key state, so input-event numbering and queued events during pairing do not
change the button behavior. A debounced press/release enters the shared
30-second pairing routine. Long holds do not invoke the HiSilicon upgrade
service. The selected peer is saved to `KA_PEER_CONFIG`; it
survives power cycles when fpvOS mounts its persistent settings directory.

Two LED-class outputs, `p1-air:status-0` and `p1-air:status-1`, carry the existing
status pattern: output 0 for pairing, output 1 flashing while disconnected or
waiting for video, and output 1 steady while streaming. Physical P1 checks
confirm output 0 is red and output 1 is green; wiring and active-low polarity
belong to the device tree. Physical press/release successfully pairs and saves
the receiver. An 11.6-second hold caused pairing only on release, with no upgrade
or restart. Red during pairing, blinking green when disconnected, and steady
green with red off during video have been visually confirmed.

## Durable settings

fpvOS mounts a dedicated directory from P1's existing user-data UBIFS volume at
`/var/lib/kestrel-air`; factory calibration remains read-only. The launcher
requires that writable mount before starting Kestrel. Application defaults and
paired receiver settings use `KA_CONFIG` and `KA_PEER_CONFIG` as before.

Both settings writers replace files atomically: write a same-directory temporary
file, flush and fsync, rename, then fsync the directory. Errors are propagated;
the pairing log does not claim a receiver was saved if writing fails. Existing
regular-file permissions are preserved, new files are mode 0600, and symlink or
special-file destinations are rejected. A process killed before rename cannot
truncate the previous settings; a leftover temporary file is never used as the
active configuration. The `make test` storage checks cover these failure cases.
